# 单元测试反馈设计 V0.2

## 目标

单元测试页面不能只在最后显示“通过 / 失败”。

用户需要能够在运行过程中判断：

> 系统走到了哪里？这一小步做了什么？结果是否可信？为什么可以继续？

但也不能把底层网络日志、Python traceback、每条 HTTP 请求直接倾倒给用户。

因此采用三层反馈。

## 第一层｜运行总览

页面顶部始终显示：

- 单元名称；
- 运行任务编号；
- 运行模式；
- 市场截面；
- 当前阶段；
- 总状态；
- 已完成步骤 / 总步骤；
- 警告 / 错误数量。

前台中文状态：

- 等待执行；
- 运行中；
- 通过；
- 有警告；
- 失败；
- 已阻塞；
- 需要人工处理。

机器内部仍可保留稳定英文枚举。

## 第二层｜步骤卡片

每个“业务上可判断”的小步骤一张卡。

每张卡固定回答：

1. 本步目标；
2. 输入；
3. 动作；
4. 关键结果；
5. 审计；
6. 本步结论。

结论必须是本步骤自己的自然语言结论，不能复制最终结论。

## 第三层｜可展开审计明细

默认折叠，用户需要时展开。

包括：

- 数据来源；
- 排除对象；
- 排除原因分组；
- 缺失对象；
- 跨源冲突对象；
- 差异最大的样本；
- 原始文件 / JSON 路径；
- 必要的技术异常信息。

原则：

> 先给结论，再给证据；默认不让技术细节淹没业务判断。

## Market Map 数据获取单元当前步骤

### S0｜冻结本次运行

显示：

- 运行编号；
- 运行模式；
- 市场截面。

局部结论：

> 本次运行身份和市场时点已冻结，可以开始取数。

### S1｜获取主行情

显示：

- 主数据源；
- 候选对象数量；
- 唯一代码数量；
- 有价格对象数量；
- 重试状态。

局部结论：

> 主行情取得成功，可以进入可转债范围筛选。

### S2｜可转债范围筛选

显示：

- 候选数量；
- 基础样本数量；
- 排除数量；
- 排除原因分组；
- 可展开查看每一个被排除对象。

当前典型原因：

- 尚未形成有效上市交易价格；
- 已上市但当前无有效交易价格；
- 定向可转债 / 非公开品种；
- 正股价格缺失或异常；
- 转股价缺失或异常。

### S3｜补充到期日

显示：

- 基础样本数；
- 到期日覆盖数；
- 缺失数；
- 缺失对象。

原则：

> 缺少到期日只影响期限 / 规模样本，不反向删除基础样本。

### S4｜补充剩余规模

显示：

- 期限样本数；
- 规模样本数；
- Size 缺失 / 异常数；
- 辅助源额外对象。

当前要求：

```text
remaining_size > 0
remaining_size <= issue_size
```

辅助源额外对象只能展示和审计，不能反向扩大主 Universe。

### S5｜多来源交叉审计

显示：

- CV 自算差异；
- 转股价跨源冲突；
- 到期日口径差；
- CV 差异最大的对象；
- warning / unresolved。

当前可展开表：

1. CV差异最大的10只；
2. 转股价跨源冲突；
3. 到期日跨源口径差异。

### S6｜数据准备完成

显示：

- 基础样本；
- 期限样本；
- 规模样本；
- Support Zone；
- Core Zone。

局部结论：

> 数据获取单元已经生成结构化、可审计样本，可以交给市场价值映射计算单元。

## 三种运行模式

### 1. 盘中测试

`LIVE_TEST`

作用：

- 测真实数据源；
- 测实时网络；
- 测盘中字段同步性。

不能冻结为正式 Market Snapshot。

### 2. 历史回放测试

`REPLAY_TEST`

作用：

- 使用已经成功保存的固定原始输入；
- 稳定测试 Gate、Audit、页面反馈和回归；
- 不受实时数据源临时故障影响。

历史回放与正式计算共用同一业务处理代码，不另造一套“假逻辑”。

### 3. 正式收盘截面

`CLOSE`

作用：

- 未来正式生成可供下游使用的 Market Valuation Map Snapshot。

必须使用真实、统一、可审计的收盘截面。

## 反馈节奏原则

- 一步完成即刷新，不等整个单元结束；
- 只展示业务上有意义的步骤，不展示每个函数调用；
- “有警告”不等于“失败”；
- 失败必须明确停在哪一步、为什么停、后续哪些步骤没有执行；
- 被排除对象必须可展开；
- 异常 / 差异对象必须可展开；
- 所有步骤同时保留机器 JSON，页面负责中文可读表达；
- 正常运行自动推进，不要求用户逐步点击“继续”。

## 人工交互边界

只有出现：

- 已阻塞；
- 需要人工处理；

程序才暂停并请求人工或 AI 处理。

这样既保持 Engineering 控制外循环，又保留必要的人类控制点。
